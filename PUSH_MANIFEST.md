PUSH_MANIFEST for Sentinel-Core
=================================

Purpose: list repository items that MUST exist in the online repo (cannot be obtained elsewhere), and items that should NOT be pushed.

Essential (push these)
- `README.md`: project overview and usage.
- `SENTINEL_CHECKLIST.md`: governance and release checklist.
- `ARCHITECTURE.md`: system architecture (diagrams/intent).
- `openapi.json` and `docs/api/openapi.json`: canonical API contract (single-file API spec).
- `docs/diagrams/*`: source diagrams (PlantUML/Mermaid) and generated SVGs used in docs.
- `crates/sentinel_policy/POLICY_EVALUATED.md`: canonical `PolicyEvaluated` event documentation.
- `docs/api/` static docs that cannot be regenerated by CI without work (small, textual assets).
- `scripts/` small helper scripts (`run_bench.sh`, `run_bench.ps1`) used to reproduce runs.

Optional (usually present in source repos; include only if you want a full remote copy)
- `crates/*` (crate sources): these are source code and normally belong in the repo, but per current directive they are optional to avoid large pushes. If you want a canonical online repo for others to clone and build, include all `crates/`.

Do NOT push
- `target/`, `target/**` and other build artifacts.
- Local bench raw output (e.g. `crates/sentinel_bench/bench-results/*`) unless explicitly required.
- Dev/test private keys, PEMs, `.env` files, secrets, or any credentials.

Rationale
- The online repo should contain immutable, canonical artifacts that cannot be reliably reconstructed (API contract files, governance docs, canonical event docs, and small reproduction scripts).
- Large generated build artifacts and secrets should never be pushed.
